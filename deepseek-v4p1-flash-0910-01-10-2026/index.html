A computer that never existed — running live below

VOLTA·16

What follows is not an emulator for a machine you can buy. It is a machine built from nothing: a 16-bit CPU, its instruction set, the assembler that compiles for it, the firmware burned into its ROM, the video hardware, the sound chip, and seven pieces of software written in its own assembly language. It exists entirely in the files beside this page and runs in your browser. You can power it on, play the games, read every line, and rewrite them.

Operating notes

  1. Every cartridge on this page is assembly source. It is assembled when you insert it, by the assembler in js/volta.js.
  2. Edit any cartridge in §03 and press Assemble & run. Errors are reported with line numbers, like a real toolchain would.
  3. The machine executes a fixed budget of 204,800 cycles per frame — about twelve megahertz — and then the display refreshes. WAIT yields the rest of the frame.
  4. Deep links work: #snake, #fire, #life, #chiptune, #cube, #boot.

02

The Library

Seven cartridges ship with the machine. Each one is a single text file of assembly, assembled by the page when inserted, editable down to the last byte. The readouts on each card are measured from the assembled ROM, not written by hand.

      05
      
      
      The Manual
      
      
      
        Everything a programmer needs to write software for this machine.
        The reference tables are generated from the same source the CPU
        executes, so they cannot drift out of date.
      
      
    
      

    
      
      
      
        
      1. Words, registers, flags
      
        
      
          Everything in VOLTA-16 is a 16-bit word. The machine has eight
          general registers, R0–R7, a program counter,
          a stack pointer that starts at 0xFFFF and grows down, and
          four flags: Z (zero), C (carry / borrow), N
          (negative, the top bit of the result) and V (signed overflow).
          Comparison instructions set the flags by subtracting; conditional
          jumps read them. Signed comparisons use JL/JGE
          (N ≠ V), unsigned ones use JB/JAE (C).
        
      

        
      2. The frame
      
        
      
          The machine runs a fixed budget of 204,800 cycles per display
          frame and then hands you a fresh one. Most instructions cost one
          cycle; memory access and branching cost two, DIV and
          MOD cost eight. WAIT gives the rest of the
          frame back to the display hardware, which is the polite thing to do
          when you have finished drawing early.
        
      

        
      3. Video
      
        
      
          The frame buffer is 160×120 words at 0x4000, one word per
          pixel, low nibble = palette index 0–15. The palette is sixteen
          registers: write the index to PAL_INDEX, then 4-bit
          values to PAL_R, PAL_G,
          PAL_B and the screen updates immediately. A hardware
          fill engine blasts colour through memory: write FILL_COLOR,
          then FILL_LEN, then the destination to
          FILL_START and it is filled before the next instruction.
        
      

        
      4. Sound
      
        
      
          Three channels — two pulses and one noise — live at
          0xE020. A channel's period p produces
          12288 / (p + 1) hertz. The control word packs
          bit0 = on, bits1–4 = volume 0–15,
          bits5–6 = duty (12.5%, 25%, 50%, 75%). Channel 2
          interprets its period as a noise clock. Master volume is one
          register; mix it yourself.
        
      

        
      5. Input and chance
      
        
      
          INPUT returns a bitmask: left/right/up/down, A, B,
          START, SELECT. RNG reads a fresh 16-bit
          pseudo-random number every time — written to, it reseeds.
          FRAME counts frames since reset. There are no
          interrupts; the machine is simple on purpose.
        
      

        
      6. The firmware
      
        
      
          The top of the address space holds a 3.5-kiloword system ROM,
          assembled by the same assembler from js/bios.asm.js.
          It provides screen clearing, pixels, rectangles, lines, the 5×7
          system font, decimal printing, and a sine table with signed
          lookups. Every routine saves and restores R0–R7, so you
          can call the ROM from anywhere without fear. Here is a complete
          program:
        
      
        
      ; say hello, politely, for one second
    LDI R0, 0
    CALL BIOS_CLR          ; black screen
    LDI R0, message
    LDI R1, 8
    LDI R2, 56
    LDI R3, 1              ; palette colour 1
    CALL BIOS_PRINT
loop:
    WAIT                   ; yield the rest of the frame
    JMP loop
message:
    .asciiz "HELLO, WORLD"
      
        
      

        
      7. The assembler
      
        
      
          Labels are name:; constants are
          .def NAME value. Data arrives as
          .word (with full expressions and character literals),
          .ascii/.asciiz and
          .space/.fill. .org moves the
          assembler's pen. Expressions support + - * / % & | ^ ~
          << >>, parentheses, 0x,
          0b, $ and 'c' literals.
          The assembler reports overlapping writes, unknown symbols and
          out-of-range immediates with line numbers.

      8. How this was made
      
      
      
        One session, no frameworks, no build tools, no image files. The
        machine, its assembler, its firmware and its seven cartridges are all
        hand-written text in this folder; the page loads ES modules straight
        from the same directory it is served from. There is a small test suite
        (npm test) that assembles every cartridge headlessly and
        checks the geometry, the game rules and the clock, because a machine
        that never existed should still be honest about whether it works.
      
      
      
      
        Everything you see is 16-bit. The cube's 32-bit multiplier is built
        out of shifts and adds, because that is what the hardware gives you.
        The chiptune is a real tracker. The fire is a real cellular field.
        The font is 64 glyphs drawn on paper first. If you find something
        beautiful here, it is because it was kept simple enough to be read.
